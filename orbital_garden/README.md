# orbital_garden

轨道花园不是简单种植：**光照、水分、收成互相影响**。作物只有在水分与光照
同时充足时才会在每个时钟 tick 生长，成熟后才能交付订单；水分、光照每 tick
各消耗一份，任一耗尽则停长。

## 规则（rule_a ~ rule_j）

| 规则 | 行为 |
| --- | --- |
| `rule_a` | 重复作物检查：种植槽内同名作物视为重复，返回 False。 |
| `rule_b` | 时钟推进：运行中每 tick +1，并在水、光均充足时让作物生长、消耗水/光各一份。 |
| `rule_c` | 订单交付：订单为空时**不返回任何文本**（False）；非空时按 FIFO 交付队首订单。 |
| `rule_d` | 播种：种植槽已满（已用槽位达到容量）时拒绝，返回 False，不会越槽播种。 |
| `rule_e` | 灌溉：暂停/锁定区域拒绝浇水；否则单次灌溉累计一次水分。 |
| `rule_f` | 灌溉计数：单次灌溉只累计 **1** 次，不重复累计。 |
| `rule_g` | 养分扣除：余额不足 5 时拒绝，不扣成负数，返回 False。 |
| `rule_h` | 养分转运：从 `src` 扣 5，同时向 `dst` 如数入账 5，不少算。 |
| `rule_i` | 收获审计：先到先收，只返回最早一批（同名）作物的记录，后到作物不会顶替。 |
| `rule_j` | 种植槽闸口：槽位达到容量上限时返回 False，禁止继续播种。 |

## 暂停 / 恢复行为

- `pause(state)` 后进入暂停：`rule_b` 不推进时钟、作物不生长、不消耗水/光，
  `rule_e` 灌溉被拒绝（对应“锁定区域不浇水”）。
- `resume(state)` 后从冻结的时钟值继续，**不补跳**暂停期间的 tick；作物
  生长进度、水分、光照保持暂停时的数值，不会凭空增减。
- 灌溉计数（`rule_f`）、养分转运（`rule_h`）为即时操作，恢复后照常执行，
  暂停期间没有补发，因此不存在重复累计。

## 存档 / 读档与损坏存档行为

- `save_game(state, path)` 将完整状态（含 `next_id`）写成 JSON。
- `load_game(path)` 返回 `(state, ok)`：
  - 正常读档时保留存档中的 `next_id`，后续作物编号**连续、不跳号**。
  - 文件缺失、无法读取、JSON 非法或顶层不是对象时视为损坏：**不抛异常**，
    返回 `(new_game(), False)`，从全新状态开始（`next_id` 重置为 1），
    旧状态不会被半读入内存。
- `reset(state)` 清空全部运行状态（作物、订单、水、光、养分、时钟、
  `next_id` 等），与 `new_game()` 完全一致，不存在残留。

## 测试与命令

- 测试保持原样：`python -m unittest discover -s tests`（10 个用例全部通过）。
- 命令入口保持原样：`python engine.py`，支持 `run` / `quit`。
