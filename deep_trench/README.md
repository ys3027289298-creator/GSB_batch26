# 深海海沟探测任务（deep_trench）

潜水器下潜海沟、采集样本、管理氧气的任务存档模块。正式实现位于 `save.py`；
`engine.py` 仅为兼容旧 `import engine` 的转发层，二者行为一致。

## 十项问题修复对照

| # | 问题 | 修复位置 | 修复后行为 |
|---|------|----------|------------|
| 1 | 重复样本 | `rule_c` | 样本登记幂等，同一编号重复登记返回 `False` |
| 2 | 样本舱满仍采集 | `rule_f`、`collect_sample` | 舱满时采集返回 `None`，样本舱与计数不变 |
| 3 | 空样本返回文本 | `rule_d`、`view_sample` | 空舱或编号不存在返回 `None`，不再返回占位文本 |
| 4 | 先到样本未登记 | `rule_h`、`rule_e` | 待登记队列先进先出；按最小到达序号取最早样本 |
| 5 | 暂停仍下潜 | `rule_b`、`dive` | 暂停或舱门关闭时下潜返回 `False`，深度氧气不变 |
| 6 | 查看样本误删 | `rule_e`、`rule_i`、`view_sample` | 查看/计数均为只读，不移除任何样本 |
| 7 | 氧气少算 | `rule_a` | 余量不足 10 时拒绝扣减；扣减额准确记入 `dst`，不出现负氧 |
| 8 | 单次采集重复累计 | `rule_g` | 计数幂等，同一编号只累计一次，重复调用返回 `False` |
| 9 | 重置不清 | `reset_mission` | `state.clear()` 后回填初始值，`next_id`、队列、计数全部归零 |
| 10 | 读档跳号 | `rule_j`、`load_game` | 先取号后自增；读档完整恢复 `next_id`，编号连续不跳号 |

## 暂停 / 恢复行为说明

- `pause_mission(state)`：任务进入暂停。之后 `dive` 返回 `False`、
  `collect_sample` 返回 `None`，深度、氧气、样本舱、待登记队列全部冻结，
  已采集样本与登记信息原样保留。
- `resume_mission(state)`：从冻结点继续，氧气、深度、样本编号无缝衔接。
- 幂等性：未暂停时重复 `pause`、暂停中重复 `resume` 均返回 `False` 且不改变状态。
- 持久化：暂停标志随 `save_game` 写入存档；读档后仍处于暂停，必须显式
  `resume_mission` 才能继续行动。

## 损坏存档行为说明

`load_game(path)` 在以下情况视为存档损坏：文件不存在、内容不是合法 JSON、
字段缺失或类型非法（如 `next_id` 不是正整数）。此时行为约定为：

- **不抛异常**：调用方永远拿到一个可用的状态对象；
- **不覆盖原文件**：损坏的存档保留在磁盘上供排查，`load` 只读不写；
- **重新开局**：返回 `new_game()` 的全新初始状态，并额外置
  `state["save_recovered"] = True`，调用方可据此提示
  “存档损坏，已重新开局”；
- 正常存档则完整恢复全部字段（`events` 的整数编号键从 JSON 字符串键还原），
  `next_id` 精确恢复，随后采集的样本编号连续，不会跳号。
